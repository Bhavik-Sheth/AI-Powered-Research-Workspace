# DB Layer — Design & Architecture

TLDR: `backend/db/` is two files — `db/__init__.py` (247 lines: pooled async engine, the `session()` context manager, Alembic migration runner, and four hand-written SQL primitives) and `db/models.py` (678 lines: the full SQLAlchemy 2.x ORM schema, 24 tables). Every other backend module reaches Postgres exclusively through `db.session()`; there is no other connection path. Four SQL primitives — `hybrid_retrieve`, `traverse_graph`, `filter_unseen`, plus migrations — live here because they cross table/module boundaries or need raw SQL SQLAlchemy's expression language can't express cleanly (recursive CTEs, RRF fusion, `unnest`-driven anti-joins). Everything else — inserts, selects, updates — is done by callers directly against the ORM models inside a `db.session()` block; `db/` itself does no per-table CRUD.

## Storage / data model

24 tables (`db/models.py`), one class each, DDL owned by Alembic migrations (`backend/alembic/versions/`, 16 revisions) — models.py explicitly disclaims being the source of truth for constraints (`models.py:4-9`: "See Alembic revisions for DDL... this module only maps them").

**Settings / infra (no `project_id`)**
- `api_keys` (`models.py:39-55`) — single-row store, `CHECK (id = 1)`. Holds `providers` (JSONB), `primary_model`/`auxiliary_model` strings, `vault_path`, `voice_engine`, onboarding timestamp.
- `scheduled_jobs` (`models.py:58-74`) — catch-up-on-launch cursor: `job_kind`, optional `project_id` (no FK — table predates `projects` in migration order), `interval_seconds`, `last_run_at`, `next_due_at`.
- `result_store` (`models.py:76-92`) — server-side tool-result cache keyed by `result_id` (string PK), `tool_name`, `ui_view`/`model_view`, `expires_at`.

**Projects / papers**
- `projects` (`models.py:94-118`) — `id`, `name`, `slug` (unique), `focus_seed`, `interest_profile` (JSONB), `corpus_centroid` (768-dim `Vector`, nullable), `tab_stack`/`active_tab`, timestamps.
- `notes` (`models.py:121-152`) — `id` has **no** `server_default`: generated by Vault Writer and never re-derived. `UniqueConstraint(project_id, file_path)`. `eager_defaults=True` mapper arg so `updated_at` comes back via `RETURNING` on UPDATE (asyncpg has no lazy-reload fallback).
- `papers` (`models.py:155-207`) — global, keyed by `canonical_id` (unique). Five independent pipeline-state columns (`fetch_state`, `parse_state`, `embed_state`, `extract_state`, `references_state`), each `CHECK IN ('queued','running','done','failed','degraded')`. `canonical_id_source CHECK IN ('doi','arxiv','openalex','s2')`.
- `paper_content` (`models.py:210-226`) — 1:1 with `papers` (PK = `paper_id`, no own `id`). `full_text`, `sections`/`references`/`datasets`/`code_links` as JSONB, `parser_version`, `parsed_at`.
- `quote_anchors` (`models.py:228-250`) — shared anchor object reused by card fields, highlights, matrix cells: `quote`/`prefix`/`suffix`/`char_start`/`char_end` (`CHECK char_end > char_start`), optional `page_hint`/`bbox_hint`.
- `paper_cards` (`models.py:253-276`) — one row per extracted field, `field_key CHECK IN ('problem','method','datasets','results','limitations')`, `UniqueConstraint(paper_id, field_key)`. Absence of a row *is* "not stated" — no boolean flag.
- `paper_edges` (`models.py:279-313`) — global graph: `src_type`/`dst_type CHECK IN (paper,author,dataset,repo,topic,method,concept)`, `relation CHECK IN (cites,cited_by,authored_by,uses_dataset,has_code,has_topic,method_of,related_method)`, `provenance CHECK IN (metadata,llm)`, identity `UniqueConstraint` over all 6 columns (idempotent upsert target).
- `idea_edges` (`models.py:315-349`) — project-scoped graph half, `project_id`-keyed, own `src_type`/`dst_type` value set including `note`/`experiment`/`highlight`, `relation CHECK IN (inspired_by,uses_dataset,references_note,relates_to,contradicts)`, `provenance` adds `'user'` to metadata/llm.
- `project_papers` (`models.py:352-367`) — composite PK `(project_id, paper_id)`, the only place a paper becomes project-specific. `relevance CHECK IN (relevant,somewhat,not,unset)`, `why_relevant`, `resume_position` (JSONB).
- `highlights` (`models.py:370-383`) — reader highlight, reuses `quote_anchors`, optional `note_id` (`ON DELETE SET NULL`).

**Conversations**
- `conversations` (`models.py:386-397`) — one thread per project. `summary`, `summarised_through_seq`, `last_message_at`.
- `messages` (`models.py:400-421`) — verbatim transcript. `role CHECK IN (user,assistant,tool_call,tool_result)`, `input_modality CHECK IN (text,voice)`, `UniqueConstraint(conversation_id, seq)`, optional `result_id` FK into `result_store` (`ON DELETE SET NULL`), `citations` JSONB, `interrupted` bool.

**Memory / chunks**
- `paper_chunks` (`models.py:424-440`) — global, `source_type CHECK IN (paper_section, abstract)`, `char_span` (`INT4RANGE`), `embedding` (768-dim `Vector`), `tsv` — a `Computed`, persisted `to_tsvector('english', text)` generated column.
- `project_chunks` (`models.py:546-563`) — identical shape plus `project_id`, `source_type CHECK IN (note, experiment, conversation_summary)`.

**Experiments**
- `experiments` (`models.py:443-479`) — `slug` unique per project, `status CHECK IN (planned,remaining,in-progress,done)`, `setup` JSONB, `network_optin`/`gpu_optin` bools, `notebook_path` nullable until Vault Writer runs once. `eager_defaults=True` for the same PATCH/`RETURNING` reason as `notes`.
- `experiment_runs` (`models.py:482-511`) — one container execution's fingerprint. `run_kind CHECK IN (clean_run_all, interactive)`. `approved_at` is `NOT NULL` — a row cannot exist without a validated confirmation token (the consent-gate invariant is enforced at the DB row level, not just in application code).
- `experiment_metrics` (`models.py:514-543`) — `source CHECK IN (user, measured)` — no `llm` value exists, so an LLM-authored metric is structurally unrepresentable. Second CHECK: `source <> 'measured' OR run_id IS NOT NULL` — a measured metric must cite its run. `run_id` FK is `ON DELETE RESTRICT`.

**Matrix / writing**
- `matrices` (`models.py:566-583`) — `selected_paper_ids`/`selected_experiment_ids` as Postgres arrays (not join tables — row order is part of the artifact), `column_defs` JSONB.
- `matrix_cells` (`models.py:586-615`) — `source CHECK IN (extracted, user)`; `source='extracted'` requires `anchor_id IS NOT NULL`; exactly one of `paper_id`/`experiment_id` must be set (`CHECK ... = 1`); `UniqueConstraint(matrix_id, paper_id, experiment_id, column_key)`.
- `documents` (`models.py:618-639`) — one LaTeX manuscript, `.tex` file is truth, `body` is an indexed mirror. `last_compile_engine CHECK IN (swiftlatex, tectonic)` (nullable).

**Feed**
- `feed_items` (`models.py:642-661`) — one surfaced candidate per project poll. `canonical_id` carries **no FK** — a feed candidate is deliberately not yet a `papers` row. `state CHECK IN (new, saved, dismissed)`, `UniqueConstraint(project_id, canonical_id)`.
- `seen_set` (`models.py:664-678`) — dedup ledger, composite PK `(project_id, canonical_id, reason)`, `reason CHECK IN (read, library, surfaced, dismissed)`, `canonical_id` again has no FK.

## Core mechanics

**Engine / session (`db/__init__.py:20-33`)**
- One module-level `AsyncEngine` created at import time from `get_config().database_url` (asyncpg driver) — no explicit `pool_size`/`max_overflow` args, so SQLAlchemy's async default pool sizing applies.
- `_session_factory = async_sessionmaker(_engine, expire_on_commit=False)` — objects stay usable after commit without a refetch.
- `session()` is an `@asynccontextmanager`: yields a session, commits on clean exit, rolls back and re-raises on any exception. This is the **only** sanctioned unit-of-work boundary — every caller opens one `async with db.session() as session:` block per logical operation.

**Migrations (`db/__init__.py:36-50`)**
- `run_migrations()` wraps a synchronous Alembic `command.upgrade(cfg, "head")` in `asyncio.to_thread` — called once at startup (`main.py:133`, inside `lifespan`, gated behind Docker readiness) so the blocking call doesn't stall the event loop, but only because it happens before any request is served.
- `sync_database_url` (psycopg driver, `config.py:49`) is used only for this Alembic run; the app's normal runtime path is `database_url` (asyncpg).
- `dispose()` (`db/__init__.py:53-54`) tears down the engine's pool — called at shutdown (`main.py:154`).

**`hybrid_retrieve` (`db/__init__.py:122-151`) — the memory fusion query**
1. Two independent raw-SQL "arms" run as separate statements against different tables: `_PAPER_ARM_SQL` (`paper_chunks` joined through `project_papers` to scope by project membership) and `_PROJECT_ARM_SQL` (`project_chunks` scoped directly by `project_id`).
2. Inside each arm, two CTEs run **independently**: `dense` (pgvector cosine distance `<=>` against `:embedding`, ranked via `ROW_NUMBER()`, capped at `k=50`) and `lexical` (`ts_rank` against a `plainto_tsquery('english', :query_text)`, same cap).
3. Each arm fuses its own dense+lexical ranks with **reciprocal rank fusion**: `COALESCE(1/(60+dense_rank),0) + COALESCE(1/(60+lexical_rank),0)`, keeping any row that appeared in either list (`LEFT JOIN ... WHERE dense.id IS NOT NULL OR lexical.id IS NOT NULL`).
4. Both arms execute against the same `session`, then Python code (`db/__init__.py:149-151`) concatenates the two row lists, sorts by score descending, and truncates to `limit` (default 20, caller passes 40) — the merge across arms happens in application code, never in one SQL statement.
5. An optional `types` filter (list of `source_type` strings) is applied inside each arm's `WHERE` via `CAST(:types AS text[]) IS NULL OR ... = ANY(...)` — `NULL` means "no filter."

**`traverse_graph` (`db/__init__.py:159-216`) — the recursive graph walk**
1. `roots` — a list of `(node_type, node_id)` tuples — is unnested into a CTE (`roots`), giving the recursive query its starting node set.
2. `graph_edges` is a `WITH RECURSIVE` CTE: the base case selects any `paper_edges` row touching a root node (`hop=0`); the recursive case joins `paper_edges` to the growing `graph_edges` set on **any** of 4 src/dst combinations (undirected expansion), incrementing `hop`, bounded by `WHERE ge.hop < :depth`.
3. The final `SELECT` unions the (optionally `types`-filtered) `paper_edges` walk with **all** `idea_edges` for the project (unioned in flat, un-traversed, since idea edges are already project-scoped — no need to walk them).
4. An empty `roots` list still executes correctly: `unnest` on empty arrays yields zero rows, so the `paper_edges` side contributes nothing and only `idea_edges` come back — "never an error" per the docstring (`db/__init__.py:207-208`).

**`filter_unseen` (`db/__init__.py:224-247`) — the feed dedup anti-join**
1. `unnest`s the candidate `canonical_ids` into a virtual row set.
2. Excludes any id present in `seen_set` for the project (any `reason`), and separately excludes any id already in the project's library (a live `NOT EXISTS` join through `project_papers` → `papers.canonical_id`, not a materialized `seen_set` row) — so every paper-adding code path doesn't need to remember to also write a `seen_set` row.
3. Short-circuits to `[]` for an empty input list before hitting the DB at all (`db/__init__.py:244-245`).
4. Docstring explicitly disclaims order preservation — caller must re-key by id.

## Callers & dependents

`db.session()` is used from essentially every domain module and API router — confirmed via grep across `backend/`: `api/anchors.py`, `api/conversations.py`, `api/experiments.py`, `api/feed.py`, `api/graph.py`, `api/highlights.py`, `api/matrix.py`, `api/notes.py`, `api/papers.py`, `api/projects.py`, `api/runs.py`, `api/settings.py`, `api/writing.py`, `feed/__init__.py`, `graph/__init__.py`, `harness/__init__.py`, `jobs/__init__.py` (imported as `from db import session`, used for `ScheduledJobs`/`Project` catch-up reads), `llm/__init__.py` (two deferred/local `import db` calls inside `_resolve_tier`, explicitly to avoid a circular import with `settings/`), `memory/__init__.py`, `papers/__init__.py`, `sandbox/__init__.py`, `scripts/configure_provider.py`, `search/__init__.py`, `voice/__init__.py`, `ws/__init__.py`. Every sampled call site opens `async with db.session() as session:` — the pattern is used consistently, no module opens a raw connection or a second session factory.

Every ORM table has at least one confirmed reader/writer outside `db/`: `ApiKeys` — `llm/__init__.py`, `settings/__init__.py`; `ScheduledJobs` — `jobs/__init__.py`; `ResultStore` — `search/__init__.py`; `Documents` — `vault/models.py`, `vault/__init__.py`, `writing/__init__.py`; `Matrices`/`MatrixCells` — `matrix/__init__.py`; `PaperEdges`/`IdeaEdges` — `graph/__init__.py`. No table defined in `models.py` was found orphaned.

The three raw-SQL primitives each have exactly one caller in the live codebase:
- `hybrid_retrieve` — `memory/__init__.py:183`, inside `query_memory`, which is itself only called from `harness._maybe_retrieve` (per `memory_design.md`'s own finding — not re-verified here since it's outside `db/`'s scope, only the `db/`-side call is confirmed).
- `traverse_graph` — `graph/__init__.py:79`, inside `get_graph`, the read path behind the Graph View.
- `filter_unseen` — `feed/__init__.py:224`, inside the Research Feed candidate-dedup pass.

`run_migrations`/`dispose` are called exactly once each, from `main.py`'s `lifespan` (startup/shutdown respectively) — no other caller.

## Open questions / rough edges

- **No pool tuning.** `create_async_engine(get_config().database_url)` (`db/__init__.py:20`) passes no `pool_size`, `max_overflow`, or `pool_timeout` — runs on SQLAlchemy's async defaults. Fine for a single-user desktop sidecar, but nothing in the code documents that this was a deliberate choice versus an oversight.
- **`hybrid_retrieve` merges two arms in Python, not SQL.** The docstring (`db/__init__.py:130-136`) calls this out as intentional ("never materialised into one table"), but it means the final `limit` truncation happens after two full round-trips and a Python sort — no `LIMIT` pushdown across arms, no way to short-circuit if one arm alone already satisfies `limit`.
- **`traverse_graph`'s recursive join is a 4-way OR across (src,dst) pairs** (`db/__init__.py:176-180`) with no direction distinction preserved in the walk itself — hop counting treats the graph as undirected even though `paper_edges.relation` encodes directional semantics (`cites` vs `cited_by`). Whether a `cited_by` edge should count as a "different" traversal than `cites` isn't distinguished by the walk, only by what's stored in the resulting rows.
- **`filter_unseen`'s library check is a live join, not a cache.** Correct by the docstring's own reasoning, but it means every feed-dedup call re-joins `project_papers`→`papers` for the whole project rather than reading a precomputed set — no index hints or table sizes were inspected to know if this matters in practice.
- **Two tables (`scheduled_jobs`, `result_store`) carry no FK on `project_id`** (`models.py:61-63`, `models.py:79-81`) — the code comments explain this is a migration-ordering artifact (`projects` didn't exist yet when these were created), not a permanent design choice, but nothing in `db/` enforces that the FK gets added later; it would take a fresh migration read to confirm whether it ever was.
- **`feed_items.canonical_id` and `seen_set.canonical_id` carry no FK to `papers`** (`models.py:645`, `models.py:667`) — deliberate per the docstrings (a feed candidate isn't a `papers` row yet), but it does mean `db/` cannot enforce referential integrity between a "seen" id and any real paper; that burden is entirely on callers.
- **`llm/__init__.py` imports `db` locally inside a function**, not at module top, to break a cycle with `settings/` (`llm/__init__.py:150-153`) — a real, working workaround, but it means `db` has at least one consumer that can't import it normally, which is a signal of a tighter coupling between `llm` and `settings` than the module layout otherwise suggests.
